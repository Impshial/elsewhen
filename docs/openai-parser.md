# OpenAI parser

The parser proposes a canonical action. The local engine alone checks scope, rules, outcomes, turns, and state. There is no model-generated world state or narration.

## Configuration

In **Settings**, enter an OpenAI API key, select a model ID, enable natural-language interpretation, and save. The initial model is `gpt-4.1-mini`; the adapter requires Responses API structured outputs. The timeout is configurable. **Test connection** makes one real request and reports whether a valid interpretation was received. Requests are billable to the configured account. No paid requests were made during development verification.

The key remains in the Electron host process. When **Remember** is selected, Electron `safeStorage` encrypts it with the platform facility. On systems without protected storage, ElseWhen retains it only for the current session. Linux's plaintext `basic_text` backend is explicitly rejected. The renderer gets only a `hasKey` flag; project files, exports, saves, scenarios, and normal logs contain no credential. Removing the key removes its stored ciphertext.

## Local commands first

Conventional syntax is interpreted locally even when OpenAI is enabled. Only an unsupported local interpretation is sent to the model. Supported forms include `look`, `inventory`, `examine anchor`, `go stone arch`, `take token from case`, `open case`, `unlock gate with token`, `use shard on anchor`, `put token in case`, `give token to archivist`, `talk to archivist`, and `ask archivist about observatory`. The sample defines `say "Meridian" to prism console`.

An ambiguous reference opens clarification without a turn. The next answer fills the missing slot while retaining other bindings. Numbers select offered candidates. Pronouns use recent entity referents. Semicolons outside quotes form an explicit queue of at most eight commands; failure or clarification pauses the queue. Undo, load, restart, cancellation, and source-session changes invalidate pending provider work.

## Request boundary

`OpenAIParser` calls the official SDK's `responses.create`, uses `text.format` with a strict JSON schema generated by `zodTextFormat`, sets `store: false`, limits output to 1,800 tokens, and disables automatic retries in the host. Prompt version: `elsewhen-intent-v1`.

The input contains the player's command and bounded public context: current observed location, visible or remembered entities, visible exits, known dialogue topics, public action definitions, recent transcript entries, referents, and pending clarification. The builder caps entity/exit/topic counts and recent history. It does not serialize author rules, hidden destinations, private examples, variables, unread book text, or the project graph. A readable object's text reaches context only when it has actually appeared in the player's transcript.

The schema is a nested envelope with `schemaVersion: 1` and a `result` of `intent`, `clarify`, or `unsupported`. Arguments are tagged entity, connection, topic, text, number, or boolean values. The response cannot contain narration, state changes, confidence scores, or arbitrary executable code. Local semantic validation checks action IDs, parameter names, types, supplied IDs, clarification candidates, and required arguments. The engine then independently rechecks canonical arguments and world-state constraints.

No source notes or hidden puzzle answers are sent automatically. Player commands and observed story text do leave the machine when interpretation is needed, and the connection test sends a small public fixture. `store: false` requests no stored Responses object; it does not establish a provider-wide retention guarantee. Review the provider's current data controls for your account before sending sensitive story text.

## Failures and diagnostics

Incomplete responses, refusals, malformed JSON, invalid identifiers, authentication failures, rate limits, timeouts, and network errors produce controlled messages. They do not consume a turn or commit an action. Requests carry an abort signal; session epochs and revisions discard late results. The designer can inspect the actual parser input/interpretation, model, prompt version, latency, and returned token usage. These are local session diagnostics, cleared by starting a fresh session.

## Tests and evaluation

`pnpm test` runs conventional parser tests, schema/semantic tests, mock transport tests for completed/incomplete/refused output, and session cancellation tests. It makes no network requests.

`pnpm eval:parser` prints opt-in instructions without calling OpenAI. To run the small billable evaluation suite, set `OPENAI_API_KEY` in the host environment and run `pnpm eval:parser --live`. Optionally set `ELSEWHEN_MODEL`. Results include prompt version, model ID, semantic pass/fail, interpretation, and token usage. No key is printed. This initial suite is a smoke evaluation, not evidence of comprehensive natural-language accuracy.
